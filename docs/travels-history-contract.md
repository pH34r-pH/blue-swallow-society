# Canonical observation history (code-only)

Travels uses `POST /api/cybermap/history`, forwarded to `POST /api/v1/cybermap/history`. Both enforce the existing verified-owner read boundary; configured delegated API credentials require `Owner.Read`. Anonymous requests and forged platform principal headers do not grant access. No new mutation or custom write proof exists.

The JSON body accepts `from`, `to` (UTC RFC3339, up to six fractional digits), `deviceId`, `sessionId`, `kind`, `limit`, `cursor`, and `selectedId`. Unknown fields fail with 400. Intervals are half-open and at most 31 days; arbitrary historical intervals remain queryable. Limits are integers from 1 through 200 (default 50). Radio kinds are `wifi_ap`, `ble_device`, and `cell_signal`. Selection/session IDs are lowercase canonical UUIDs; installation IDs remain bounded opaque strings under the existing producer contract. Browser filter URLs contain these selectors, never coordinates or raw radio identifiers; API filters are sent in the body.

`vm/cybermap-api/src/history-query.mjs` validates the request and exports `readHistory(body, {store, now})`. The store interface is `store.queryHistory(query)`, implemented by isolated `history-store.mjs` through a read-only transaction with a three-second statement timeout. No migration is introduced. Pagination orders exact PostgreSQL microsecond capture timestamps and canonical IDs descending. A filter-bound opaque cursor carries the last key and ingestion cutoff, excluding observations ingested after page one. This cutoff is not a long-lived MVCC snapshot and does not promise stability across deletion or historical correction.

The response schema is `bss.observation_history.v1`: `observations`, independently filter-checked `selected`, `nextCursor`, `filters`, `retrievedAt`, and `snapshotAt`. Rows contain canonical ID, stored session/producer IDs, kind, capture/ingestion times, `captureLocation`, nullable measurements, and `emitterLocation: null`. Coordinates describe observed capture position, not inferred transmitter position. Null/absent/empty/invalid/nonfinite measurements remain null; finite numeric values, including zero and PostgreSQL numeric strings, survive. Explicit SQL projection suppresses radio identities, payloads and provenance; public/DeFlock sources are excluded. No new identifier hashes or changes to installation HMAC boundaries occur.

Stored session IDs form queryable observation-backed groups. Rows without a stored session stay ungrouped. The UI counts groups on the current page, explicitly not complete trips. It does not manufacture sessions from nearby viewport results. Selection and filters restore on reload/Back; superseded requests are aborted/ignored. Empty/error states clear old rows. Retrieval age of 60 seconds is visibly stale without changing capture time. List/detail and keyboard navigation work without graphics. The optional existing MapLibre renderer draws valid capture points only, with an OpenStreetMap raster basemap; no connecting trajectories or inferred emitters are generated.

Synthetic validation covers real PostGIS joins, microsecond ties, paging, null/zero, source exclusion, stable off-page detail, HTTP auth, request races, stale/empty/error/reload/keyboard/mobile, and rendered-map/fallback flows. Production-volume latency and private-data acceptance require separate approval before deployment. This increment neither deploys nor changes live auth/settings, schemas, jobs, paper data or hosting wrappers.
