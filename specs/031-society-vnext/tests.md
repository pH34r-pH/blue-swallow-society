# Society vNext validation

## Authentication and release seam

Use generated synthetic keys/passwords and an ETag-enforcing table fake. Cover
correct/wrong/oversized password, malformed verifier/configuration, global and
caller throttle, storage outage, session expiry, renewal at the absolute bound,
logout versus renewal, rotation, token tampering, purpose confusion, Origin,
method/body limits, and denial before private storage access. Exercise real
handlers, not just string inspection. Existing owner, device and machine-feed
tests must continue passing.

For the migration format, derive a synthetic legacy digest independently and
verify the original password works, wrong passwords and the digest as a password
fail, and format confusion does not authenticate. Preserve direct-scrypt tests.

For browser downloads, verify authorization before store construction, exact
package/channel/signer validation, immutable version/source binding despite
latest changes, APK/FAP allowlisting, missing release and private/no-store HEAD.
In Chromium, copy the secret-free phone URL, sign in from a separate mobile-sized
context, follow the protected artifact redirect to synthetic download bytes, and
verify the originally selected release survives a current-pointer change. Check
that the cross-origin artifact receives no browser session credentials, checking
for updates displays the newer receipt, and lock denies another grant. Synthetic
browser delivery does not establish Android installation or live Blob delivery.

## Public and private browser journeys

Test root remains public with a session; explicit Login; wrong password; safe
return routes; session restore on private deep link; owner step-up; lock across
tabs; expired/failed bootstrap; private memory and DOM teardown. Inspect actual
rendered layouts, keyboard focus, 200% zoom, reduced motion and WebGL fallback.
Verify ordinary password login, map and downloads cause no owner-auth request;
the explicit Admin login alone starts the existing owner flow without forwarding
the viewer token. Separately prove owner identity checks and deny viewer tokens
on admin APIs. Future entity inspection tests must prove shared-read access and
anonymous, cross-group, write and unshared-legacy-data denial.

Hold owner restore and login-start requests open to verify bounded recovery and
an enabled retry button. Race a late restore response or timeout against a newer
login and verify it cannot replace the pending login state. Distinguish an API
`invalid_password` response from platform HTML/empty 401, `session_expired` and
storage-unavailable responses in the password dialog. These synthetic checks do
not establish a successful password or Microsoft sign-in on the deployed host.

## Data and birding

Android/browser golden fixtures must agree at a shared revision on admitted
facts, subject identity, uncertainty and contributor scope. Exercise signatures,
conflicts, retraction/cutoffs, unknown wire versions and bounded interruption.
Bird imports require idempotence/corrections, presence-only counts, private draft
isolation, explicit publication and complete unpublish from all public outputs.

Dataset transport must deny before storage construction for anonymous and
cross-group sessions; verify service-signed roster against current control
state; return only bounded exact bytes for a roster member and fixed path;
reject traversal/query/write attempts; and fail closed on authority changes,
missing/partial/oversized streams and storage deadlines. It must never issue
SAS grants or expose control-state invitations. Worker admission is a separate
required validation surface before this transport can drive the map.

Wire tests consume synthetic bytes generated by the pinned actual Kotlin
`DatasetWire` implementation. Verify v1 closed and v2 live batches, exact signed
head/commit hashes, unknown observation byte retention and lossless 64-bit
clocks. Exercise signature/header/publisher mismatch, noncanonical envelopes,
unknown versions/fields, duplicate IDs, byte/count budgets, unsupported records,
invalid control policy/outcome/order, Stop and retraction constraints. Run the
same codec in a real Chromium worker with unsafe-eval prohibited. This proves
the wire seam only; shared admission/projection parity needs further fixtures.

Admission tests must exercise whole-batch atomicity, exact-byte duplicates,
cross-publisher geometry ambiguity, cross-kind conflicts, quarantine capacity,
tombstones before targets, per-publisher suppression, sticky cutoffs and incorrect
historical hashes. Validate whole control-journal appends before mutation, including
health/checkpoint linkage, boot/mode/elapsed continuity and final Stop. Capacity
failures must not half-admit facts or advance a cursor.

Reader tests must cover signed roster monotonicity/equivocation, observed head
rollback/forks, missing payloads, peer isolation, fair progress under tiny budgets,
cancel/resume, clear versus late callbacks, auth teardown and safe error codes.
Bridge tests bound streamed bodies, check response authority headers, reject
arbitrary destinations and distinguish missing heads from missing immutable data.
Real Chromium journeys use the site's CSP without unsafe-eval and actual producer
bytes through the real private asset/API guards: explicit load, unchanged-head
refresh, cancellation/resume, cutoff revision, clear, outage retry and Lock during
a pending read. These do not replace full Android Room admission/projection parity.

The receiver map browser journey must load verified producer fixes, reject stale
generations, remove points after a signed cutoff or clear, and deny anonymous
renderer assets. Verify that no OpenStreetMap tiles are requested until the
basemap action is explicitly selected. Verify lock removes the map and workers.
Exercise keyboard selection and verify that signed cutoff and clear remove both
map details and inspector content from the prior generation.
Switch between all contributors and individual members, including an empty
scope. Rapid changes must supersede earlier in-flight projection responses.

## Launch evidence

Prepare two frontend candidates from the same tracked commit and compare every
manifest hash. Verify omission of the managed API runtime and authoring file,
preservation of application routes, invalid-commit rejection and refusal to
overwrite an existing candidate. A local candidate is not an attested release.
The public image workflow also packages and inspects the candidate on pull
requests. A semantic release must verify both frontend and OCI attestations for
the same source and tag; retry reconciliation fails if its advertised frontend
asset or attestation is missing.

Record exact source/artifact/runtime versions. Verify live auth/storage rules
and signed artifact download separately, then real phone fresh install/update,
local recording and invited contribution. Tests or fixtures never substitute
for the required host or physical-device evidence in #124.

For the initial no-users cutover authorized on 2026-11-10 Pacific, record release
publication, protected backend configuration and canonical frontend deployment
as distinct evidence. Probe the public journal, anonymous private-route denial,
forged platform identities, password/session lifecycle and private downloads.
Backend-only probes do not establish canonical-origin integration or a valid
password session. Rollback planning/rehearsal is not a cutover requirement;
authentication and privacy checks remain required.
