# Test Design

| ID | Authority | Validation | Expected evidence |
|---|---|---|---|
| TST-020-01 | FR-004 | Render `local-proof/compose.yaml`; assert the API uses `PostgresObservationStore`, Caddy and API preserve their loopback-only upstream boundary on an internal proof network, only the opaque relay also joins the edge bridge and publishes host `:18080` to Caddy `:8443`, and PostGIS is a disposable named volume. | `docker compose config`, container inspection, a source-contract test, and a host loopback probe. |
| TST-020-02 | FR-004/FR-007 | Start the local stack with a known public desktop fingerprint; reject no-client-cert, wrong client certificate, spoofed proxy headers, and mismatched device identity. | Caddy/API status codes and sanitized logs. |
| TST-020-03 | FR-003/FR-006 | Apply every migration to fresh PostGIS and seed exactly one enabled owned desktop source/device credential with the exact two scopes and exact desktop local-proof provenance. Assert stale/substituted source or credential state (extra scope, disabled, expiry, changed fingerprint, or changed metadata) fails rather than being reused at both mTLS lookup and the locked write transaction. Assert count-only preflight shows exactly one named desktop source and one matching desktop credential before any batch. Assert bootstrap and runtime readers accept only the fixed named credential paths and one new exact `local-proof.env`, reject symbolic links, Windows junction/reparse traversal through explicit reparse-attribute checks, and resolved-root escapes before credential access, emit Compose's required variables, verify direct Windows ACLs against the stated current-user-only direct-access boundary, and verify one passwordless P12 client-certificate/private-key identity matching the single public leaf. | Migration table, count-only seed query, policy unit tests, bootstrap/runtime junction negative-path evidence, P12 structural contract, and redacted ACL verdict. |
| TST-020-04 | FR-006/FR-007 | Deliberately remove the proof volume before startup; require count-only `desktop_source=1`, `desktop_credential=1`, `sync_batches=0`, and `observations=0` before the batch, then submit an accepted batch twice through Caddy and require `1/1/1/1` counts afterward. Require a strict v1 receipt schema (no missing or extra durable fields), validate every v1 receipt field, and require canonical equality of the full first/replay receipt. Assert the local verifier caps JSON before parsing, loads only P12/CA values from the exact protected environment, and refuses a substituted direct P12/CA value. | Redacted receipt schema, count-only database evidence, source/runtime contract evidence, and negative stale-volume/receipt-mutation tests. |
| TST-020-05 | FR-005 | Android source and package contract: only an explicit debug property selects `https://bss.localhost:18080`, `.localproof`, and the property-gated local CA resource; `BssMtlsTransport` must construct an explicit local-CA trust manager only in that property-gated variant and retain platform trust otherwise. Manifest URI scheme, exported control actions, signature control permission, and runtime action constants derive from the final application ID; END/SCAN/PAUSE receivers must require that signature permission. Ordinary debug and release cannot contain the endpoint/local CA/suffix. | Targeted JVM contract test, normal/debug-local/release assemblies, static APK inspection, and a separately signed emulator sender denied control delivery. |
| TST-020-06 | FR-002/FR-005/FR-009 | Android runtime and source contract: import the PFX into KeyChain, select the alias, and show that the app stores only the alias; no PFX appears in APK/assets/app storage. Assert every `KeyChain.choosePrivateKeyAlias` path hops to the UI thread before persistence, Toast, upload/portal, or MapLibre work. | Emulator UI/ADB package-state evidence and focused callback contract test without key bytes. |
| TST-020-07 | FR-007 | Android runtime: a controlled encrypted v2 outbox item persists before upload, releases only after a valid closed-schema local `bss.sync_receipt.v2` with closed `bss.wardriver_progress.v1` fields, and stays/retries for invalid/missing/extended/duplicate-member receipt, changed locally bound receipt, or rejected identity. Persist an encrypted canonical receipt binding before the local progress marker or terminal rename. Requeue one uploaded encrypted envelope unchanged and require the same full durable v2 receipt semantics with no additional `sync_batches` or observations. | Emulator KeyChain/ADB package-state evidence, encrypted-envelope and encrypted-binding state counts, receipt-bound binary progress marker/cursor, and count-only PostGIS v2/idempotency evidence. |
| TST-020-08 | FR-001/FR-008 | Key Vault metadata proves the separate desktop certificate name, client-auth policy, exportability, enabled state, tags, and expiry; public PEM bundle contains primary + desktop leaves only. | Redacted Azure metadata / public fingerprint inventory. |
| TST-020-09 | FR-008 | The host-side verifier accepts only the exact deployed Azure mTLS origin, uses only the fixed protected passwordless desktop P12 after direct ACL/public-leaf verification, bypasses proxy configuration for the no-client TLS probe, bounds each JSON response to 64 KiB before parsing, and proves the desktop client identity yields one v1 receipt plus a canonically identical full replay receipt. | CI deployment receipt, Caddy/API/database count-only evidence, receipt-mutation unit tests, and redacted verifier output; no Android-to-Azure claim. |
| TST-020-10 | FR-002/FR-006 | The deliberate next `proof` run removes prior local containers/volumes before fresh evidence; after a successful run the disposable stack may remain only for bounded operator inspection. Remove protected temporary copies and ephemeral probe artifacts; Git status/source scans show no private material, connection strings, or raw test observations. | Docker inspection, file ACL checks, `git diff --check`, and redaction scan. |
| TST-020-11 | FR-010 | Run normal debug/release validation without a network reference refresh. Inspect the explicit refresh tasks: each remote reference artifact downloads to a temporary candidate, matches a reviewed SHA-256 pin before replacement, and replaces the tracked input only after verification. | Gradle contract test and ordinary debug/release build evidence. |

Run TST-020-05 RED before Android build-logic/resource changes. Run TST-020-01/02/03/04 RED before creating the local harness. No live Azure trust change or smoke run occurs before TST-020-01 through TST-020-07 pass.
