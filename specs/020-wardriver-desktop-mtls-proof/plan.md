# Plan

1. **Credential and source boundary.** Create the Key Vault certificate `wardriver-mtls-desktop-dev-2026` from a policy derived from the existing client-auth contract: self-issued, RSA-3072, exportable PKCS#12, `clientAuth`, digital signature/key encipherment, 24-month validity, and explicit desktop-development tags. Store the passwordless desktop P12 only at its fixed user-protected local path. Extract only its public leaf PEM and SHA-256 fingerprint for Caddy/credential binding. Bootstrap and both host verifiers must verify a single passwordless client-certificate/private-key identity whose leaf matches one fixed public PEM before a TLS request. Direct Windows ACLs grant only the operator's current Windows account; Windows `Administrators` and `SYSTEM` can take ownership outside the boundary and are not trusted direct principals. This is not an anti-malware or hostile-admin sandbox. Do not retrieve, print, or commit the primary PFX.
2. **Local backend harness.** Add `vm/cybermap-api/local-proof/compose.yaml`, `Caddyfile`, a non-secret `.env.example`, `Dockerfile`, and deterministic scripts to (a) wait for PostGIS, (b) apply the existing `db/migrations` files, (c) seed one owned desktop source/device credential from a supplied public fingerprint, and (d) expose bounded count-only desktop-source/desktop-credential/batch/observation evidence. Caddy and the API share an internal proof network namespace so the API admits only a loopback Caddy upstream. A separate relay attaches to both the internal proof network and a distinct edge bridge, publishes host `:18080`, forwards opaque bytes to Caddy `:8443`, and cannot inject headers or terminate TLS. Node and PostGIS have no host port. The deliberate `proof` entrypoint removes the disposable volume before startup; the verifier independently requires a `1/1/0/0` named-desktop-source/matching-desktop-credential/batch/observation preflight before it transmits a batch.
3. **Local TLS material.** Add a local-only certificate generation command that writes a local CA, a `bss.localhost` server leaf, and Caddy inputs under ignored `.local/`. It may consume the desktop **public** PEM as Caddy’s client trust input. Bootstrap accepts no caller-selected certificate/lab path: it resolves the named fixed materials, permits only a new exact `local-proof.env`, rejects detected reparse traversal through both link and Windows reparse attributes, atomically refuses overwrite, emits Compose's exact variable names, validates size/ACL/single-P12-identity/leaf correspondence, and hardens/verifies Windows ACLs. The local CA private key and desktop PFX never enter the repository.
4. **Android local-lab boundary.** In `app/build.gradle`, make the local lab an explicit debug-only property. An ordinary debug build defaults to the deployed Azure origin and excludes the local CA/trust resource; only `-PbssLocalMtlsLab=true` adds the local-proof resource source, selects exactly `https://bss.localhost:18080`, and adds application-id suffix `.localproof`. Release never reads the property or includes the suffix/local trust. Derive manifest URI scheme, exported control actions, signature permission, and runtime action constants from the final application ID so primary and localproof packages can co-install. Keep the main network configuration and release resource path free of local trust.
5. **Android identity boundary.** Make debug development builds use the distinct desktop device identity, while release retains the primary identity. Use the existing KeyChain chooser and alias storage; every chooser callback must marshal to the main thread before any persistence, Toast, upload/portal, or MapLibre/UI action. Do not add PFX file access to app code.
6. **Automated guardrails.** Add RED/GREEN Android contract tests for debug-only endpoint/trust and co-install external-identifier boundaries. Add backend tests/scripts that fail if the local stack uses an in-memory store, exposes Node externally, omits `require_and_verify`, accepts an unbound/stale desktop source or credential, loads unrelated protected-environment values into the verifier, accepts a substituted or multi-identity P12 path, omits fixed-P12 leaf/ACL/reparse checks, buffers an unbounded JSON response, accepts an incomplete/extended/duplicate-member receipt or changed replay semantics, skips exact pre/post count checks, or persists local certificate/private-key material in tracked paths. The Android outbox must encrypt a canonical durable-receipt binding before local progress or terminal transition. Reference-data refresh must verify reviewed SHA-256 pins on temporary candidates before atomically replacing tracked inputs.
7. **Local evidence run.** Use the deliberate `run-local-proof.sh proof` command to remove the prior local volume, build containers, run migrations and seed, validate Caddy, and execute the host verifier. It must prove `1/1/0/0` named-desktop-source/matching-desktop-credential/batch/observation preflight, mTLS, one complete UUID-bound v1 receipt, canonical full-receipt replay equality, and `1/1/1/1` post-replay counts. Import the desktop PFX into the emulator, install the local-lab debug APK, submit one controlled v2 queued batch, verify database state/a closed v2 receipt/encrypted receipt binding/outbox transition, and retry the exact batch. A successful disposable local stack may remain for bounded inspection; the next `proof` run resets it, while `down --volumes --remove-orphans` is explicit teardown. Capture redacted receipts and count-only DB evidence.
8. **Azure promotion.** Build a public PEM bundle from the existing primary public entry plus the new desktop public entry; update the protected CI secret, deploy through the existing OIDC workflow/IaC route, and create/bind the matching Azure source/device credential. Run one bounded host-side Azure smoke against the exact deployed FQDN with the same fixed protected passwordless desktop P12, direct ACL/leaf validation, a no-proxy no-client probe, response-size bounds, and canonical full-v1-receipt replay comparison. Record cert version/fingerprint metadata without secret material. Do not claim an Android-to-Azure transition: Android evidence remains the local proof; Caddy/API/database receipt/replay evidence establishes the live smoke.
9. **Documentation and drift.** Amend `specs/014-wardriver-mtls-direct-api/` from singular to bundle/multiple-identity language; update the new feature’s test/tasks artifacts as each implementation receipt lands. Run `graphify update .` in both repositories after source changes.

## Constraints

- Windows Docker Desktop requires elevation to enable `Microsoft-Windows-Subsystem-Linux` and `VirtualMachinePlatform`; do not substitute an untrusted container runtime.
- The Azure VM trust file is supplied by a protected public-PEM CI secret and rendered through `infra/main.bicep` / `infra/vm-echo-lab.bicep`; do not patch it manually on the VM.
- The existing Cloud deployment workflow uses a committed source revision. The Azure smoke is run after local proof and a reviewed CI deployment.
