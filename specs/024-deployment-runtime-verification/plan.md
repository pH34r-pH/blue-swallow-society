# Implementation Plan: Deployment Runtime Verification Gates

**Spec**: [spec.md](./spec.md)

1. Add a `validate-source` GitHub Actions job. Use Node 22 for API/root contracts and Node 24 for VM contracts. Install `api` and `vm/cybermap-api` from their lockfiles with lifecycle scripts disabled. Run the hermetic root suite, VM suite, installer shell syntax check, and a no-network JSON parse of every `api/**/function.json`. Scope OIDC permission to Azure-mutating/verification jobs rather than this repository-code validation job.
2. Make `deploy-infra` and `deploy-app` depend on `validate-source`.
3. Move the public VM release receipt write until after all migrations succeed. Query the database migration ledger and record only revision, archive digest, UTC timestamp, and its JSON migration list.
4. Add `scripts/verify-deployment-runtime.mjs`, a bounded process runner, a redacting Azure CLI adapter, and a bounded custom-domain OIDC/ARM wrapper. Every workflow Azure CLI invocation goes through the adapter; it applies a monotonic hard execution deadline—including a close observed at the deadline—bounded capture, ordinary process-tree termination, an explicit safe child-environment allowlist, sensitive-argument rejection, mode-0600 result-file handoff, and local-only diagnostics. The custom-domain wrapper receives only the OIDC variables it requires and suppresses raw child diagnostics. The verifier uses the same bounded policy, bounded fetch reads, validates the VM receipt and service state through Azure Run Command, retries backend health/readiness, and calls the existing metadata-only protected release probe.
5. Add a post-deploy `verify-runtime` job with OIDC Azure login. Install Node 24 in each deployment job that invokes a bounded wrapper, derive resource names locally, materialize secure ARM parameter, Azure result, and merged SWA app-setting JSON only in mode-0600 temporary files, pass only file references to Azure CLI, remove the files on exit, validate Azure deployment outputs in a scrubbed local helper before it serializes fixed-schema values to `GITHUB_OUTPUT`, scope and clear the dynamic SWA deployment token immediately after its action, invoke the verifier, and pin every workflow Action to a reviewed immutable commit.
6. Lock contract coverage in `tests/deployment-runtime-gates.test.mjs`; run it red before source edits and green afterward.
